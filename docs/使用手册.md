# ai-drama-desk 使用手册

> 本手册承接工作台 CLI、LoRA 管理和仓内 skill 的详细用法；总体定位、安装指南与模型下载清单见仓库根 [README](../README.md)，agent 驱动 playbook 见 [AGENT.md](../AGENT.md)。

## 1. 定位与架构

- 上游输入是一份「分镜稿 md」（契约与最小示例见 README「输入契约」节），不预设产稿方；本工作台是消费分镜稿的本地制片路径。
- Web UI 和 CLI 都通过 `http://127.0.0.1:7799/api/v1` 操作同一服务；服务端是业务规则的唯一真相源。
- ComfyUI 负责本地推理；LoRA 训练由独立 Trainer Adapter 管理。
- 参考训练环境：Windows + 24G 级显卡（如 RTX 4090）+ musubi-tuner（Qwen Image Edit adapter）。

## 2. 安装与启动

```bash
cd ai-drama-desk     # 你克隆下来的仓库目录
bun install
bun run start
```

打开 `http://127.0.0.1:7799`。源码形态运行 CLI：

```bash
bun run cli -- --help
bun run cli -- health --json
```

如服务端不在默认地址（PowerShell / bash 任选其一）：

```powershell
$env:GITRUCK_AI_DRAMA_DESK_URL = "http://127.0.0.1:7799/api/v1"
```

```bash
export GITRUCK_AI_DRAMA_DESK_URL="http://127.0.0.1:7799/api/v1"
```

### 安装仓内 skill 到本机 Agent

```bash
bun run cli -- skills install                        # 自动探测本机 Agent（Claude Code / Codex / Cursor / Gemini CLI 等）
bun run cli -- skills install --agents codex,cursor  # 只装指定宿主
bun run cli -- skills install --copy                 # 不用链接，各宿主复制一份
```

统一正本落 `~/.agents/skills`，再链接（Windows 为 junction）到各 Agent 兼容目录；链接不可用时自动回退复制。

## 3. 画风资产

```bash
bun run cli -- style list
bun run cli -- style create --file ./profile.json
bun run cli -- style edit my-style --file ./patch.json
bun run cli -- style delete my-style --replace-with fallback-style --yes
bun run cli -- style delete my-style --force --yes
bun run cli -- style export my-style --out ./my-style.style-pack.json
bun run cli -- style import ./my-style.style-pack.json --conflict rename
```

`profile.json` 最小示例：

```json
{
  "id": "my-style",
  "name": "My Style",
  "styleLock": "中文画风锁定词",
  "negatives": "不希望出现的特征",
  "refs": []
}
```

- 被项目引用的画风默认禁止删除；选替代画风，或明确 `--force`。
- Style Pack 默认不包含参考图和 LoRA 权重。要包含参考图时同时传 `--include-refs --license-confirmed`（请确认你对参考图有再分发权利）。
- 画风删除是永久操作，不会自动重建；分享和备份请用 `style export`。
- 项目创建后仍可在项目页切换画风。服务端会校验目标画风并把 `styleRefPicks` 重置为新画风前两张默认参考图；生成任务在途时禁止切换。
- 「本地 ComfyUI · B（LoRA）」与当前项目所选画风强绑定：该画风没有 `lora` manifest 时，选项置灰，API 也会拒绝提交。

### 3.1 参考策略与单人单图集（本地 ComfyUI A/B 档）

每个 keyframe 引擎声明自己的**参考策略与预算**：本地 ComfyUI A/B 档 = 每角色单人 1 图（总预算 3）、Seedream = 每角色多图直喂（总预算 10，见 3.2）、mock = 不消费参考图。角色源图（三视图/神态图）每角色只上传一次、两个参考集共享；项目页角色资产区会随当前 Keyframe 引擎自动切换到对应参考集视图，顶部徽章常显当前策略。

「本地 ComfyUI · A（参考图）」会从每镜 cast 解析实际出场角色，并按出场顺序各取一张**单人单图集**里的主参考。只要镜头中有明确角色，就不再用含人物的画风锚图补满参考图槽；画风由 Style Lock 文字约束承担。空镜最多使用一张画风锚图。出场角色超过预算时，超出的角色不再静默无参考，任务会带显式告警点名被裁减的角色。

角色设定原图可以是正面、侧面、背面并排的三视图，但三视图不能直接作为 A/B 档的稳定输入：Qwen Image Edit 可能把三个完整人形理解成三个人。上传后，在角色卡点击源图打开**裁剪画布**：空白处拖出选框、框内拖动平移、八向手柄缩放、方向键微调（Shift=10px）、比例锁（自由/1:1/3:4）；「整图 / 左·中·右 1/3」保留为一键快捷预设，落位后可继续拖拽细调；右侧预览为真实裁剪渲染。横排三视图（宽高比 ≥2.5）打开时自动预置中间 1/3；同一源图二次编辑会回填上次裁剪。保存后原始设定图保持不变，裁剪结果单独存放。

角色卡会显示以下状态：

- **已配置单人主参考**：生成使用预览中的派生图或显式整图。
- **兼容回退**：旧项目暂时使用第一张原图；若它是三视图，存在复制人物风险，应尽快裁出单人主参考。
- **缺少参考图**：当前角色没有可提交的视觉参考。

提交时，提示词会按 cast 顺序写入 `Picture 1 = 父亲`、`Picture 2 = 女儿` 等明确映射。未使用的 ComfyUI 可选图片输入会被真正断开；纯黑图也会被 Qwen 编码成一个 `Picture`，因此不能作为“没有参考图”的占位符。画风档案只提供去除主体身份后的绘画语言；“画外的人”等叙事信息会编译为不可见方向，避免生成额外听众或旁观者。cast 形如 `女儿（父亲虚在前景）` 时，会解析为女儿和父亲两位，而不是因括号内文本误选父亲、漏掉女儿。

源图管理：每张源图右上角悬停可删除（被单人主参考引用为 source 的源图会被拒删，先更换或清除主参考）；上传按文件内容魔数校验，仅接受 png/jpg/webp 且单文件不超过 20MB。

### 3.2 多图直喂集（Seedream）

Seedream 5.0 Pro 支持最多 10 张参考图，适合直接吃三视图原图。切到 Seedream 引擎后，角色资产区变为**多图勾选墙**：

- **默认全选**：角色的全部源图默认入选，新上传的源图自动纳入；点图可排除/恢复，「恢复默认全选」一键清掉自定义记录。
- **预算分配**：多名角色总入选超过 10 张时，先保证每名有入选源图的角色至少一张（集内首张），其余按角色轮转补齐；被裁减的角色会在项目页收到点名告警（成功任务的告警也会浮出，不静默）。
- **提示词映射**：同一角色的多张参考图以 `Picture N–M = 「角色」（同一角色多角度参考）`分段映射，只提取长相、发型与服装的一致性。
- **两集互不影响（严格独立）**：这里的排除/恢复不影响 A/B 档的单人主参考；反过来单人裁剪件也**绝不**混入 Seedream 的参考——全排除某角色就是真的不带该角色任何参考图。在勾选墙上点 `✂` 可从某张源图直接裁一张进单人单图集（两个空间之间的桥）。

## 4. Keyframe 和视频删除

在项目镜头卡片中，悬停到 keyframe 或视频右上角，点击 `×` 并阅读二次确认。

- 删除是永久操作，无回收站。
- 删除当前选中项会同步清空 choice。
- 删除 keyframe 不级联删除已有视频。
- 已复制到导出包的副本不受影响。
- 目标正被运行中任务占用时，服务端会阻止删除。

## 5. LoRA 训练

先在 Web 的「LoRA 训练」页运行提交前检查，或准备 `training.json`（路径请替换为你本机实际路径）：

```json
{
  "name": "my-style-v1",
  "adapter": "musubi-qwen-image-edit",
  "pythonPath": "/path/to/python.exe",
  "trainerRoot": "/path/to/musubi-tuner",
  "datasetConfig": "/path/to/dataset.toml",
  "baseModel": "/path/to/models/qwen-image-edit.safetensors",
  "vaePath": "/path/to/models/qwen-image-vae.safetensors",
  "textEncoderPath": "/path/to/models/qwen-vl.safetensors",
  "outputDir": "/path/to/lora/output",
  "outputName": "my-style-v1",
  "maxTrainSteps": 2000,
  "saveEveryNSteps": 100,
  "learningRate": 0.0001,
  "networkDim": 32,
  "networkAlpha": 16,
  "triggerWords": ["my-style"],
  "license": "self-authorized"
}
```

> `license` 字段是你对数据集授权状态的自我声明：请只用你有权训练的图片。

```bash
bun run cli -- lora train --file ./training.json
bun run cli -- lora status
bun run cli -- lora status <job-id> --json
bun run cli -- lora cancel <job-id> --yes
bun run cli -- lora resume <job-id>
bun run cli -- lora publish <job-id> --style my-style
```

训练任务状态落在 `data/lora/jobs/<job-id>/`。取消会先发优雅中断，超时后强停；恢复会从最新 checkpoint 创建新任务，已完成 step 不重复计入。发布只把带 SHA-256 的 manifest 绑定到画风，不把权重复制进 Git。

### 5.1 使用「本地 ComfyUI · B（LoRA）」出图

B 档使用 `templates/qwen-edit-keyframe-lora.json`。画风的 `lora` manifest 指向 ComfyUI `models/loras` 下的**相对路径**，例如：

```text
models/loras/<你的子目录>/<你的画风-LoRA>.safetensors
```

本仓不分发任何 LoRA 权重，模板里的 LoRA 文件名仅为示例占位。接入你自己的 LoRA 有两条路：把训练 job `lora publish` 到目标画风（自动写 manifest）；或在该画风的 manifest 中手填 `weightsPath`（相对 `models/loras`）、`triggerWords` 与可选 `training.inferenceStrength`。工作台提交 B 档时会动态覆盖模板 LoRA 节点的 `lora_name`/`strength_model` 与 prompt 前缀，不要求所有画风共用 `data/config.json` 的全局 LoRA。默认强度 `0.8`，建议先在 `0.6–0.9` 范围测试。

新安装生成的默认配置已经包含 `comfyImage2`。有角色参考图时工作台会按 cast 顺序上传单人主参考；少于三个参考时，剩余可选图片输入会在提交前断开，而不是保留纯黑占位图。B 档不会再补画风参考图，因为画风已经由 LoRA 承担；这也避免锚图中的人物侵入当前镜头。

验收顺序：

1. 在项目页选择一个已绑定 LoRA 的画风；没有绑定时 B 档会置灰。
2. 在设置页重新诊断，确认 `comfyui-image2` 的 service/runtime/workflow/nodes/models 全部“就绪”。
3. 若只缺 `loras/...`，按画风 manifest 的相对名称放置权重并在 ComfyUI 中刷新模型列表。
4. 在项目页选择「图：本地 ComfyUI · B（LoRA）」，先单独 reroll 一张；成功后再用于「全自动补齐」。

### 5.2 风格数据集原则

- 数量按“独立内容图”计算；翻转、裁剪和重复次数不算新的语义样本。
- 建议 **80–150 张高质量独立图，推荐约 120 张起跑**；若要覆盖儿童/老人/多人、室内外、昼夜、远中近景和非常规题材，可扩到 150–250 张。
- 每张 caption 必须包含统一触发词和该图的具体内容、人物、动作、场景与构图；不要让全部图片共用一条只有画风描述的 caption。
- 预留至少 12–20 个训练集从未出现的提示词作为验证集，每 100 step 固定 seed 出图；以“画风已经建立且内容服从尚未下降”的 checkpoint 早停。
- 增加图片后同步降低重复次数；重复同一批图片只增加曝光，不增加数据多样性。

## 6. ComfyUI 诊断

工作台「设置」页显示 service/runtime/workflow/nodes/models 五层状态、Python/Torch/CUDA、GPU 和显存。诊断仅读：

```bash
curl http://127.0.0.1:7799/api/v1/diagnostics/comfyui
```

- ComfyUI 界面当前打开的无关 workflow 缺模型，不会影响工作台就绪度。
- 只有工作台配置的 Qwen-Edit、Wan2.2、Hunyuan 1.5 模板依赖会参与判断。
- 缺节点：安装对应 ComfyUI 插件并重启。缺模型：按诊断前缀放入 `models/diffusion_models`、`text_encoders`、`vae`、`loras` 或 `clip_vision`（下载清单见 README）。
- 诊断不访问 `/prompt`，不加载大模型，不调用计费 provider。

## 7. 数据、密钥和大文件

不进入 Git 的内容：

- `data/`：配置、用户画风、项目、媒体、LoRA job 日志。
- `lora/dataset/`、`lora/output/`、`lora/logs/`。
- 基础模型、checkpoint、LoRA 权重、参考图和生成视频。
- `.env*` 与 provider 密钥。API 只返回“已配置”布尔值。

## 8. 故障排查与回滚

- `uv` 提示 `VIRTUAL_ENV` 与 `.venv` 不一致：如 ComfyUI 已能打开且本手册的分层诊断 ready，该警告不影响工作台。不要在 IDE 命令中同时混用旧 `VIRTUAL_ENV`、`uv run` 和另一个 venv。
- LoRA 一直 `blocked`：检查工作台本地生成队列、ComfyUI `/queue` 和外部进程显存占用（本地 GPU 由训练与生成共享租约，训练在跑时本地出图/出片会排队）。
- 服务重启后原 running 任务会标记为 `recoverable`，不会假定训练仍在运行。
- 回滚时停止新 CLI 和新 API 入口即可；旧项目、画风和媒体文件格式保持可读。不要为回滚自动删除用户数据。
